# 02. 설계 메모

## 화면 구성 초안

1. **오늘의 공부**: 오늘 날짜, 과목, 강의 및 OX 체크, 달성률
2. **전체 진도**: 과목별 진도 막대와 완료·남은 강의 수
3. **목표 현황**: 완강 목표일까지 남은 날짜와 현재 남은 강의 수
4. **학습 캘린더**: 계획일, 휴식일, 완료 상태

## 날짜와 시간

- 서비스가 표시하는 날짜와 날짜 단위 계산의 기준 시간대는 `Asia/Seoul`로 고정한다.
- 날짜 전용 값은 `YYYY-MM-DD` 형식으로 다루고, 브라우저의 UTC 변환으로 날짜가 전날이나 다음 날로 바뀌지 않게 한다.
- 오늘 날짜는 기기의 지역 설정에 의존하지 않도록 한국 시간 기준으로 계산한다.
- 날짜 계산을 화면 코드 여러 곳에 반복하지 않고 날짜 유틸리티 한 곳에서 처리한다.

## 데이터 개념

- **과목**: 과목 이름, 첫 강의 번호, 마지막 강의 번호
- **학습 계획**: 날짜, 과목, 강의 범위
- **학습 항목**: 개별 강의 완료 또는 해당 범위의 OX 완료
- **진도 상태**: 학습 항목별 완료 여부

강의 진도율은 완료한 강의 수를 기준으로 계산한다. OX 완료는 별도 학습 항목으로 관리하고 강의 수 계산에는 포함하지 않는다.

## 저장 방식

- 현재 화면은 브라우저 저장으로 동작한다.
- 계정/동기화 버전은 Supabase Auth, 사용자별 행 제한(RLS), PostgreSQL 저장을 사용하도록 구현 중이다.
- 체크 기록에는 완료 시각을 저장해 계획 날짜가 바뀌어도 실제 완료 이력을 보존한다.

## 미완료 강의 자동 재배치 제안

### 기본 동작

1. 강의마다 완료 여부를 따로 기록한다. 하루 계획의 절반만 들었다면 완료한 강의는 그대로 완료로 두고, 체크하지 않은 강의만 미완료로 남긴다.
2. 한국 시간 기준으로 다음 날 앱을 열면 미완료 강의를 이후 날짜에 다시 배치한다. 날짜가 바뀌었다고 완료 기록을 지우거나 같은 강의를 중복 생성하지 않는다.
3. 남은 강의는 과목별 재생시간 평균을 사용해 공부 가능한 날짜에 시간 기준으로 고르게 나눈다. OX 복습은 해당 강의와 함께 이동하되, 강의 진도 수에는 포함하지 않는다.
4. 재배치 후 캘린더와 선택 날짜의 공부량, 과목별 진도, 전체 진도, D-Day를 다시 계산한다. 최근 조정은 취소할 수 있게 한다.

### 마감일이 가능한지 판단

- 먼저 기존의 공부 가능 요일과 하루 공부 가능 시간 안에서 목표일을 지킬 수 있는지 계산한다.
- 가능하면 목표일을 유지하며 미완료분을 자동 분산하고, 변경된 계획을 눈에 띄게 알린다.
- 불가능하면 목표일을 말없이 바꾸거나 하루 공부량을 무한히 늘리지 않는다. 필요한 하루 평균 시간과 예상 완강일을 보여주고 사용자가 선택한다.
  - 목표일을 유지하고 주말/추가 공부일을 포함한다.
  - 하루 공부 가능 시간을 늘린다.
  - 현재 공부량을 유지하고 목표일을 연장한다.
- 선택 결과는 다음 계획의 계산에 반영한다. 완료된 강의는 이동 대상에서 제외한다.

### 필요한 사용자 설정

- 공부 가능한 요일(기본값은 평일)
- 하루 공부 가능 시간
- 목표일 우선 또는 하루 공부량 우선

초기 버전에서는 강의별 재생 지점 저장 없이 체크한 강의 단위로만 완료를 판단한다. 영상 중간까지만 들은 강의는 미완료로 처리하며, 이어보기 지점 저장은 후속 기능으로 둔다.

## 기술 선택

현재 Tool Hub의 Next.js 앱에 기존 Planner를 포함하고 Vercel에 배포한다. Planner 화면은 정적 HTML/JavaScript로 유지하고, Next.js 설정 경로를 통해 Supabase 연결 정보를 전달한다.

## 구현 시 주의할 점

- 오늘 날짜에 계획이 없으면 휴식일 안내를 표시하고, 다른 날짜의 과제를 대신 보여주지 않는다.
- 날짜를 `toISOString()`으로 바로 잘라 한국 현지 날짜로 사용하는 방식은 피한다.
- 학습 계획 데이터와 완료 상태를 분리해 계획 수정이 진도 데이터에 영향을 주는 방식을 명확히 한다.
